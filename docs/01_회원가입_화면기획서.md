# 한턱 회원가입 화면 기획서 초안

처음 이용하는 사람이 기본 정보를 입력하고, 아이디 중복 확인과 이메일 인증을 완료한 뒤 데모 본인 인증으로 가입을 마치는 화면이다. 로그인 화면의 회원가입 버튼으로 진입한다.

## 서비스 목적과 대상

한턱은 선결제자가 특정 가게와 이용 대상 그룹를 지정하면, 구성원이 해당 가게에서 혜택을 나누어 쓰고 잔액과 사용 내역을 확인하는 서비스다. 첨부 기획서에서는 한 대학의 재학생·졸업생과 학교 인근 가게를 초기 검증 대상으로 제안한다.

현재는 일반 이용자의 가입 흐름을 구현한다. 가게 운영자의 가입 방식과 역할 선택은 별도 결정이 필요하다.

## 화면 정보

| 항목 | 내용 |
| --- | --- |
| 화면 식별자 | AUTH-01 |
| 진입 | 로그인 화면의 회원가입 버튼 |
| 입력 항목 | 아이디, 비밀번호, 비밀번호 확인, 이름, 생년월일, 전화번호, 이메일 |
| 추가 입력 | 인증코드 발송 후 이메일 인증코드 |
| 필수 확인 | 아이디 사용 가능, 비밀번호 일치, 이메일 인증 완료 |
| 주요 버튼 | 본인 인증하기 |
| 다음 화면 | 데모 본인 인증 완료 |
| 돌아가기 | 로그인으로 버튼 또는 뒤로가기 |

## 화면 배치

한턱 로고, 로그인으로 버튼, 회원가입 제목과 설명, 가입 단계, 필수 입력 안내, 입력 항목, 본인 인증하기 버튼 순으로 배치한다. 긴 내용은 세로로 스크롤한다. 넓은 화면에서는 최대 너비 460의 카드로 표시한다.

아이디 입력란 오른쪽에 중복 확인 버튼을 둔다. 비밀번호 아래에는 비밀번호 확인을 둔다. 생년월일 아래에 전화번호를 추가한다. 이메일 오른쪽에 인증코드 발송 버튼을 두고, 발송 후 바로 아래에 인증코드 입력란과 인증하기 버튼을 표시한다.

## 입력 규칙

입력 항목과 필수 확인 절차는 사용자 요청을 반영했다. 길이와 형식 제한은 검토 중인 기존 초안에 따른다.

| 항목 | 검사 규칙과 동작 |
| --- | --- |
| 아이디 | 앞뒤 공백 제거 후 영문·숫자 4~20자. 영문 대소문자는 구분하지 않고 중복 확인한다. |
| 비밀번호 | 공백 없이 영문과 숫자를 각각 포함한 8~32자. 특수문자 사용 가능. 기본 숨김이며 보기 전환 가능. |
| 비밀번호 확인 | 필수이며 비밀번호와 정확히 일치해야 한다. 별도로 보기 전환 가능. |
| 이름 | 앞뒤 공백 제거 후 1~50자. |
| 생년월일 | 숫자 8자리 YYYYMMDD 또는 달력. 1900년부터 오늘까지 실제 존재하는 날짜. |
| 전화번호 | 숫자와 하이픈 입력 가능. 하이픈을 제외하고 0으로 시작하는 9~11자리. 예: 010-1234-5678. |
| 이메일 | 기본 주소 형식, 최대 254자. 올바른 형식이어야 코드 발송 가능. |
| 이메일 인증코드 | 숫자 6자리. 프로토타입에서는 123456만 인증 성공. |

전화번호는 형식만 확인하며 문자 인증은 수행하지 않는다. 이메일 중복 여부는 이번 범위에 포함하지 않는다.

## 아이디 중복 확인

1. 중복 확인을 누르면 아이디 형식을 확인한다.
2. 체험용 계정과 이번 실행 중 가입한 계정의 아이디를 비교한다.
3. 이미 있으면 이미 사용 중인 아이디예요라고 안내한다.
4. 사용 가능하면 사용 가능한 아이디예요라고 표시하고 버튼을 확인 완료로 바꾼다.
5. 아이디를 수정하면 확인 상태를 해제하고 다시 중복 확인해야 한다.

체험용 아이디 hantuck01도 사용 중인 아이디로 처리한다. 대문자 HANTUCK01로 입력해도 같은 계정이다.

## 이메일 인증

1. 올바른 이메일을 입력하고 인증코드 발송을 누른다.
2. 아래에 인증코드 입력란, 인증하기 버튼, 데모 인증코드 123456 안내를 표시한다. 실제 메일은 발송하지 않는다.
3. 123456을 입력하고 인증하기를 누르면 이메일 인증이 완료되었어요라고 표시한다.
4. 다른 코드는 불일치 오류를 표시한다. 올바른 코드를 입력했어도 인증하기를 누르기 전에는 완료로 처리하지 않는다.
5. 이메일을 수정하면 발송·인증 상태와 코드 입력을 초기화한다.
6. 재발송을 누르면 기존 인증 상태와 코드를 비우고 다시 인증받는다. 데모 코드는 계속 123456이다.

완료된 인증코드 입력란과 인증 버튼은 비활성화한다. 이메일을 바꾸거나 재발송하면 다시 입력할 수 있다.

## 제출과 화면 이동

본인 인증하기를 누르면 모든 입력과 필수 확인을 검사한다. 잘못되거나 빠진 항목은 필드 아래에 표시하고, 첫 오류 항목에 초점을 맞춘다. 제출 후 수정한 내용에 따라 오류를 갱신한다.

모든 조건을 만족하면 데모 계정을 현재 실행의 메모리에 등록하고, 실제 본인 인증 없이 완료 화면을 표시한다. 가입한 아이디는 로그인 화면에 채우고 비밀번호는 비워 둔다. 완료 화면에서 로그인하러 가기를 누르면 로그인 화면으로 이동한다.

뒤로가기로 완료 화면을 나가도 로그인 화면이 나타난다. 완료된 가입 정보는 로그아웃 후에도 같은 실행 중에는 사용할 수 있다. 앱 재시작과 브라우저 새로고침 시 초기화하며, 파일·브라우저 저장소·서버에는 저장하지 않는다.

## 후속 설계 의견

이메일 인증, 개인의 본인 인증, 그룹 혜택을 받을 소속 인증은 서로 다른 목적이다. 이번 데모 이메일 코드는 실제 주소 소유를 증명하지 않는다. 실제 서비스를 연결할 때 각 인증 절차와 계정 저장·복구 정책을 구체화해야 한다.

이용약관과 개인정보 동의, 이름·생년월일·전화번호의 사용 목적은 추후 설계에서 함께 정한다.
