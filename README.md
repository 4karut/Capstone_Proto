# 한턱 Flutter 프로토타입

## 최신 프론트 서버 연동

원격 `8c56fe0`의 화면과 흐름을 기준으로 Spring Boot API를 다시 연결했습니다. 실제 진입점은 `ServerGateway`를 사용하며 기본 주소는 `http://127.0.0.1:8081/api/v2`입니다. 아래 체험 계정은 서버의 local 프로필에서만 생성됩니다. 새로고침 후에도 계정·가입·후원·즐겨찾기·가게 신청·사용 및 취소·감사 메시지/사진이 DB에 남습니다. 기존 메모리 기반 `Demo*Store`는 화면 테스트를 위해 별도로 유지합니다.

서버 실행은 `server/`에서 `./mvnw.cmd spring-boot:run`, 프론트 실행은 루트에서 `flutter pub get` 후 `flutter run -d chrome --web-port 8080`입니다. 다른 주소는 `--dart-define=API_BASE_URL=http://호스트:포트/api/v2`로 지정하세요. 서버 소스를 별도 저장소로 관리하는 경우 [백엔드 저장소](https://github.com/SeongjeLee22200525/Hantuk-backend)를 사용합니다.

실제 PG 결제·메일 발송·은행 송금·푸시는 연결하지 않은 모의 처리입니다. 서버/DB 구성·API·권한·검증은 [최신 서버 연동 문서](docs/server-v2.md)를 참고하세요. 아래 화면 설명의 메모리 초기화 안내는 원래 UI 검토용 로컬 모드에 해당합니다.


회원가입·로그인 뒤 그룹 검색, 상세, 신청 또는 초대 가입, 그룹장 승인, 즐겨찾기, 소속 그룹의 선결제 가게와 후원을 검토하는 앱입니다. 그룹 상세 상단 하트로 즐겨찾기를 지정하고, 홈의 정사각형 버튼에서 소속 그룹 리스트를 엽니다. 후원하기에서 금액 후원 또는 선결제 후원을 진행합니다.

하단 고정 바에서 홈·가게 찾기·즐겨찾기·마이페이지를 오갑니다. 가게 찾기는 소속 그룹과 관계없이 승인되어 등록된 모든 가게를 표시하고, 가게 이름으로 검색합니다. 주소는 표시만 합니다. 가게 상세에서 기존 사진, 소개·태그·주소·메뉴와 선결제 정보를 확인하고 하트로 저장합니다. 선결제를 이용할 수 없어도 상세 조회와 즐겨찾기가 가능합니다. 즐겨찾기는 그룹·가게 탭으로 나누어 표시합니다.

마이페이지에서 가입 정보와 가게 신청 상태를 확인합니다. 가게 신청 → 별도 관리자 심사 → 승인 후 공개 순서로 진행합니다. 반려된 신청은 사유를 확인하고 정보를 수정해 재신청할 수 있으며 이전 제출 정보와 사유를 차수별로 보존합니다. 승인 후 신청자 계정에서 메뉴·기존 사진 썸네일·선결제 알림과 그룹별 선결제 내역을 관리합니다.

## 실행

```powershell
git clone https://github.com/4karut/Capstone_Proto.git
Set-Location Capstone_Proto
flutter pub get
flutter run -d chrome
```

안드로이드와 iOS 프로젝트도 포함하며 모바일 실행에는 해당 SDK와 기기가 필요합니다.

## 체험 계정과 그룹

일반 계정은 `hantuck01` / `welcome123!`이며 로그인 화면의 데모 계정 채우기로 입력합니다. 직접 가입한 계정도 사용할 수 있습니다.

| 그룹 | 공개 코드 | 카테고리 | 가입 방식 | 그룹장 계정 |
| --- | --- | --- | --- | --- |
| 예시 그룹 1 | HG0001 | 학교·동문 | 신청 후 승인 | leader01 |
| 예시 그룹 2 | HG0002 | 직장·팀 | 신청 후 승인 | leader02 |
| 예시 그룹 3 | HG0003 | 취미·모임 | 초대 코드 123456 | leader03 |

그룹장 비밀번호도 `welcome123!`입니다. 공개 그룹 코드와 초대 코드는 다릅니다.

## 그룹 기능 확인

1. 일반 계정으로 로그인하고 그룹 찾기를 누릅니다.
2. 이름, 코드, #태그 또는 카테고리로 찾습니다. 빈 검색은 랜덤 순서로 표시합니다.
3. 그룹을 눌러 우측 썸네일과 소개를 확인합니다.
4. 예시 그룹 1·2는 선택 자기소개를 100자 이내 작성해 신청합니다. 비워 두어도 됩니다.
5. 완료의 확인은 홈으로 돌아가며 승인 대기로 표시합니다.
6. 로그아웃 후 해당 그룹장으로 로그인하고 그룹 신청 알림에서 승인합니다.
7. 다시 일반 계정으로 로그인하면 승인된 그룹이 드롭다운에 나타납니다.
8. 예시 그룹 3은 신청 버튼에서 123456을 넣으면 승인 없이 가입합니다.

계정 전환에는 로그아웃·로그인을 사용합니다. 새로고침이나 재시작은 기록을 초기화합니다. 예시 그룹 3에 가입하면 예시 가게 1이 표시됩니다. 총 100,000원 중 35,000원 사용, 65,000원 잔액이며 2026.11.27까지 이용할 수 있습니다. 다른 예시 그룹에는 아직 가게가 없습니다.

## 후원 기능 확인

1. 그룹 상세의 후원하기에서 금액 후원 또는 선결제 후원을 고릅니다. 가입하지 않은 그룹에도 후원할 수 있습니다.
2. 금액 후원은 금액만 입력합니다. 선결제 후원은 가게·금액·사용 기한을 입력합니다.
3. 선결제 가게 입력란을 누르면 등록된 전체 가게를 검색합니다. 검색창 옆 하트 정사각형 버튼에서는 기존 즐겨찾기 가게를 선택할 수 있습니다.
4. 확인하면 실제 청구 없이 바로 결제 완료 화면으로 이동합니다. 완료의 확인은 홈으로 돌아갑니다.
5. 선결제는 대상 그룹의 해당 가게에 새 잔액과 사용 기한으로 반영됩니다. 오늘도 기한으로 선택할 수 있고 종료일 한국 시간 23:59까지 이용합니다.
6. 그룹장 계정의 홈 → 그룹 후원 알림에서 금액·선결제 내역을 확인합니다. 가게 사장님 계정 store01 / welcome123!의 홈 → 가게 선결제 알림에서는 선결제만 확인합니다.

후원별 사용 기한과 잔액은 따로 보존합니다. 홈과 소속 그룹 상세에서는 같은 그룹의 같은 가게를 카드 하나로 묶고 합계 금액·건수·가장 빠른 기한을 표시합니다. 카드를 누르면 해당 그룹의 기한별 잔액을 확인합니다. 예를 들어 예시 그룹 3의 기존 잔액 65,000원에 100,000원을 후원하면 가게 카드 하나에 165,000원을 표시합니다. 가게 찾기도 같은 가게를 한 번만 표시합니다. 후원해도 그룹 소속이나 가게 이용 권한이 생기지는 않습니다. 외부 결제와 실제 푸시는 연결하지 않으며, 후원·알림·선결제 기록도 새로고침하면 초기화됩니다.

## 가게 신청·관리 기능 확인

1. 일반 계정으로 로그인 → 마이페이지 → 가게 신청하기에서 가게 이름·사업자등록번호·주소·카테고리·전화번호를 입력합니다. 한 줄 소개는 선택입니다.
2. 신청 후 마이페이지에서 심사 대기를 확인합니다. 대기 중에는 검색과 선결제 후원에 공개되지 않습니다.
3. 마이페이지 → 계정 설정 → 로그아웃 후 **admin01 / welcome123!**로 로그인합니다. 마이페이지 → 가게 신청 심사 → 해당 신청 → 승인하기를 누릅니다.
4. 신청자 계정으로 다시 로그인하면 마이페이지에 가게 관리가 나타납니다. 가게가 하나면 바로 관리하고 둘 이상이면 먼저 선택합니다.
5. 썸네일은 기존 사진 세 개 중 선택합니다. 메뉴 이름·가격·설명·대표 여부를 추가·수정하고 삭제 확인 후 지울 수 있습니다. 변경 내용은 공개 상세와 즐겨찾기에도 반영됩니다.
6. 가게 관리에서 선결제 알림을 확인합니다. 상단 오른쪽 선결제 관리 → 그룹 선택에서 각 후원의 사용액·잔액·기한을 봅니다. 가게 주인은 해당 그룹에 가입하지 않아도 본인 가게의 기록을 확인합니다.
7. 바로 관리 기능을 체험하려면 **store01 / welcome123!**를 사용합니다. 예시 가게 1을 소유하며 예시 그룹 3의 초기 선결제 기록을 확인할 수 있습니다.

승인된 새 가게도 가게 찾기와 선결제 후원 선택에 나타납니다. 선결제 알림은 관리 중인 가게로 한정하고, 관리 내역은 기간 종료·전액 사용 기록까지 보존하며 현재 사용 가능한 잔액을 구분합니다. 이용자 승인에 따른 프로토타입 잔액 차감은 연결되어 있습니다. 환불·실제 정산·서류 및 사업자 진위 확인은 연결하지 않았습니다. 계정 설정은 현재 가입 정보 조회와 로그아웃을 제공합니다.

실제 배민의 서류·가게 정보 등록과 심사 절차를 참고해 프로토타입에 맞게 단순화했습니다. 근거와 후속 결정 사항은 [가게 신청 기획서](docs/24_가게신청_화면기획서.md)에 있습니다. 가게 신청·승인·메뉴 변경도 새로고침하면 초기화되므로 체험 중 계정 전환은 로그아웃·로그인으로 진행합니다.

## 가게 반려·재신청 기능 확인

1. 가게를 신청한 뒤 admin01로 로그인 → 마이페이지 → 가게 신청 심사 → 신청 상세 → 반려하기를 누릅니다.
2. 반려 사유는 필수이며 최대 300자입니다. 공백만 입력할 수 없고, 취소하면 심사 대기를 유지합니다.
3. 신청자 계정으로 다시 로그인 → 마이페이지에서 반려 상태와 사유를 확인하고 정보 수정 후 재신청을 누릅니다.
4. 이전 정보를 불러온 입력란을 수정한 뒤 다시 신청하기를 누릅니다. 새 차수가 심사 대기로 접수되며 관리자 승인 전까지 공개되지 않습니다.
5. 신청 정보·이력 보기에서 각 차수의 제출 정보·사유·신청 및 심사 시각을 확인합니다. 마이페이지에는 최신 차수만 표시합니다.
6. 관리자는 재신청 상세에서 이전 이력을 확인하고 수정본을 승인하거나 다시 사유를 입력해 반려합니다. 승인 시 수정한 정보로 가게 하나가 등록됩니다.

심사 대기·승인 완료 건은 재신청할 수 없습니다. 이미 후속 차수가 접수된 이전 반려 건과 타인 신청의 재신청도 막습니다. 반려·이력은 앱 내 기록이며 실제 푸시를 전송하지 않습니다. 체험 중에는 새로고침 대신 로그아웃·로그인으로 계정을 전환하세요.

## 선결제 이용과 감사 메시지 확인

1. **leader03 / welcome123!**로 로그인 → 홈의 예시 가게 1 → 선결제 카드 선택 → 선결제 이용을 누릅니다. QR과 6자리 이용 코드를 표시하며 발급 후 10분간 유효합니다. 이때 금액은 차감하지 않습니다.
2. 이용 코드를 복사하고 로그아웃한 뒤 **store01 / welcome123!**로 로그인 → 마이페이지 → 가게 관리 → QR 결제 처리에서 코드를 입력합니다. 프로토타입에서는 이 과정으로 카메라 스캔을 대신합니다.
3. 사장님이 실제 메뉴 이용 금액(예: 9000원)을 입력하고 이용자에게 결제 확인 요청을 누릅니다. 본인 가게의 코드만 처리하며 잔액 이내 금액만 요청할 수 있습니다.
4. leader03로 다시 로그인 → 마이페이지 → 선결제 이용 내역·결제 확인 → 해당 요청 → 금액 확인·결제 승인을 누릅니다. 승인 시 소속·기간·잔액을 다시 검사하고 한 번만 차감합니다. 예시 잔액 65,000원은 9,000원 사용 후 56,000원이 됩니다.
5. 사용 완료 뒤 감사 메시지(선택, 최대 500자)와 기기 사진 1장(선택, JPG·PNG·WebP, 최대 5MB)을 첨부해 후원 메시지 보내기를 누릅니다. 건너뛰어도 사용과 알림은 유지하며 본인 이용 내역에서 나중에 한 번 보낼 수 있습니다.
6. 초기 예시 선결제의 후원자는 **hantuck01 / welcome123!**입니다. 해당 계정의 마이페이지 → 선결제 사용 알림 또는 받은 감사 메시지 보기에서 사용 내역·감사 본문·첨부 사진을 확인합니다.
7. store01 계정의 가게 관리 → 선결제 사용 알림과 선결제 관리에서 사용 내역과 변경된 잔액을 확인합니다. 가게 알림에는 후원자용 감사 본문·사진을 표시하지 않습니다.

새 선결제 후원도 실제 후원자 계정에 사용 소식과 감사 내용을 연결합니다. QR 발급·금액 요청은 사용 완료가 아니며, 취소·만료·잔액 부족·기한 종료 시 차감하지 않습니다. 이미 완료한 요청과 전송한 감사 메시지를 반복 처리해도 사용 내역·알림이 중복되지 않습니다.

사진 선택은 기기 파일 선택 창을 사용합니다. 사진과 메시지·잔액·QR 요청·알림은 현재 앱 메모리에만 보관하고 새로고침하면 초기화됩니다. 계정 전환에는 로그아웃·로그인을 사용하세요. 실제 스캐너·외부 결제·정산·푸시·이미지 서버 업로드는 연결하지 않았습니다.

## 사용 완료 결제 취소 확인

1. 선결제 이용을 완료한 뒤 **store01 / welcome123!**로 로그인 → 마이페이지 → 가게 관리 → 선결제 사용 알림에서 해당 내역의 결제 취소를 누릅니다.
2. 취소 금액을 확인하고 선택 사유(최대 300자)를 입력한 뒤 결제 취소 확정을 누릅니다. 돌아가기는 잔액을 바꾸지 않습니다.
3. 취소 가능 기간은 제한하지 않습니다. 사용 금액 전액을 실제 차감했던 원래 선결제 건에 한 번만 복구합니다. 예를 들어 65,000원에서 9,000원을 사용한 뒤 취소하면 65,000원이 됩니다. 그사이에 다른 사용이 있었다면 해당 금액은 그대로 둡니다.
4. 원래 사용 기한을 유지합니다. 기한이 지난 잔액도 복구 기록은 남기지만 다시 사용할 수 없습니다. 가게 관리에서는 만료된 복구 내역도 조회합니다.
5. 이용자는 마이페이지 → 선결제 이용 내역·결제 확인, 후원자는 선결제 사용 알림에서 취소 사유·시각·복구 금액·잔액을 확인합니다. 이미 받은 감사 메시지와 사진은 취소 표시와 함께 보존합니다.

취소된 결제의 새 감사 메시지는 보낼 수 없고 이전 QR도 다시 사용할 수 없습니다. 다시 이용하려면 새 QR을 발급합니다. 같은 결제를 반복 취소해도 금액이 중복 복구되지 않습니다. 현재는 완료된 사용 건의 전액 취소이며, 부분 취소·취소 철회·실제 현금 환불은 연결하지 않았습니다.

## 회원가입과 데모 범위

가게 기능 확인은 일반 계정 로그인 → 하단 가게 찾기 → 예시 가게 1 선택 → 하트 → 하단 즐겨찾기 → 즐겨찾기 가게 순서로 진행합니다. 그룹 가입 전에도 등록된 전체 가게를 검색하고 저장할 수 있습니다. 선결제 이용 가능 여부는 계정의 소속·잔액·기간에 따라 별도로 표시하며 만료되어도 가게 찾기와 즐겨찾기에서 계속 조회할 수 있습니다. 홈의 이용 가능한 가게는 선택한 소속 그룹의 선결제만 표시합니다.

아이디 중복 확인, 비밀번호 재입력, 이름·생년월일·전화번호, 이메일 인증이 필요합니다. 이메일 코드는 123456이며 인증하기를 눌러야 합니다. 본인 인증은 즉시 데모 완료로 이동합니다.

계정·알림·심사 이력·소속·즐겨찾기는 실행 중 메모리에 유지합니다. 실제 이메일·휴대폰 푸시·인증기관·서버는 연결하지 않았습니다. 그룹 신청 취소·거절, 코드 유효기간과 잠금 관리 화면은 후속 설계 대상입니다. 가게 신청 반려와 정보 수정 후 재신청은 구현되어 있습니다.
