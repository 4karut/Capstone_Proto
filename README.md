# 한턱 Flutter 프로토타입

공동체를 위한 가게 선결제와 QR 사용 승인 앱입니다. 제공된 `한턱_기능기획서_예시형식.docx`의 1~15번 기본 기능을 연결한 로컬 데모이며, Flutter 3.47.7 / Dart 3.13.5 환경에서 작성했습니다.

## 실행

```powershell
cd C:\Users\bdr01\!!CapstoneCode\capstone_proto
C:\Users\bdr01\!!CapstoneCode\flutter\bin\flutter.bat pub get
C:\Users\bdr01\!!CapstoneCode\flutter\bin\flutter.bat run -d chrome
```

Android 기기/에뮬레이터가 연결되어 있으면 `flutter devices`로 확인하고 `flutter run -d <기기ID>`로 실행하세요. `flutter build apk --debug`로 설치용 APK를 생성할 수 있습니다. iOS 소스도 포함되어 있으나 iOS 빌드에는 macOS와 Xcode가 필요합니다.

첫 화면의 **입력 없이 통합 데모 체험하기**를 누르면 이용자와 가게 기능을 함께 체험할 수 있습니다. 로그인 입력 시 `demo@hantteok.app` / `demo1234`를 사용합니다. 회원가입은 닉네임과 미인증 상태로 현재 기기의 체험 세션을 만들며, 실제 계정을 발급하거나 비밀번호를 저장하지 않습니다. 재로그인에는 제공된 데모 계정을 사용하세요. 모든 예시 가게와 공동체는 가상입니다.

## 체험 흐름

1. 선결제: 홈의 한턱 쏘기 → 가게·공동체·금액·조건 설정 → 요약과 잔액 정책 확인 → 모의 결제 → 선결제 상세.
2. 수혜자: 홈의 온기 식탁 혜택 → 혜택 사용하기 → 사용 QR → 가게 역할로 QR 확인 체험 → 메뉴와 주문액 입력 → 이용자 확인 요청 → 돌아온 이용자 화면에서 승인 → 사용 상세.
3. 가게: 마이페이지 → 가게 관리 모드 → 가게 선택 → 운영 현황·공동체별 선결제·거래 확인 → 정산 관리 → 날짜별 정산 상세. 사용 완료 거래만 정산 대상입니다.
4. 공동체: 홈의 공동체 카드 → 공동체 선택 → 모의 인증. 학교 이메일은 `student@hanmaeum.ac.kr`, 인증번호 `123456`입니다. 초대 코드는 학교 `CAMPUS2026`, 봉사단 `WARM2026`, 청년마을 `YOUTH2026`입니다.
5. 환불·신고: 내역 상세 → 취소·환불 / 문제 신고 → 사유·증빙 링크 입력 → 접수 → 검토 중 → 처리 완료 체험. 마이페이지의 신청·신고 현황에서도 확인합니다.
6. 실패 확인: 결제 확인의 결제 실패 체험을 켜면 혜택이 생성되지 않습니다. 잘못된 인증번호, QR 만료와 재발급, 한도 소진, 중복 승인도 확인할 수 있습니다.

## 구현 범위

| 기획서 | 구현 |
|---|---|
| 1 홈 | 공동체 전환, 인증 상태, 이용 혜택, 알림, 선결제 진입, 하단 메뉴 |
| 2 계정 | 데모 로그인, 회원가입 검증·약관, 오류 표시, 로그아웃 |
| 3 공동체 | 검색, 학교 이메일·초대 코드 인증 데모, 실패·재시도 |
| 4~6 탐색 | 검색·업종·공동체·혜택 필터, 가게·메뉴·혜택 상세, 빈 결과 |
| 7~8 선결제 | 금액·기간·한도·메뉴·공개 이름·메시지, 요약, 결제 성공·실패 |
| 9 QR | 실제 QR 이미지 생성, 3분 만료·재발급, 가게 요청, 이용자 승인·취소 |
| 10 내역 | 선결제·사용 탭, 상태·기간 필터, 상세, 사용 기록 |
| 11 마이페이지 | 프로필 편집, 공동체, 알림·설정, 가게 모드 |
| 12 고객지원 | 남은 잔액 환불 신청, 신고·정산 문의, 증빙 링크, 처리 상태 |
| 13~15 가게 | 운영 현황, QR 문자열 확인 데모, 주문·금액 입력, 가게·메뉴 편집, 일자별 정산 |

공동 잔액과 개인 사용 가능 금액을 구분합니다. 1인당 한도는 혜택 전체 이용 기간 기준의 누적 한도로 가정했습니다. 적용액은 `주문액, 남은 공동 잔액, 남은 개인 한도`의 최솟값이며, 초과액은 현장 결제로 표시합니다. 가게가 주문을 제출해도 차감되지 않으며, 이용자가 승인할 때 한 번만 차감합니다. 새 QR 발급, 취소·만료·환불 검토 상태에서는 이전 요청을 승인할 수 없습니다.

회원 프로필, 공동체 인증, 선결제·사용 내역, 알림 설정·읽음, 고객지원 신청, 가게 편집과 정산 상태는 SharedPreferences로 이 기기에 저장합니다. 유효한 QR 요청은 앱 실행 중 메모리에만 보관하며 재실행하면 무효화됩니다. 브라우저 데이터/앱 데이터를 지우면 데모가 초기화됩니다. 선결제자의 사용 기록에는 수혜자의 인증 이메일을 노출하지 않습니다.

Noto Sans KR 글꼴을 앱에 포함했습니다. 글꼴 라이선스는 `assets/fonts/OFL.txt`에 있습니다. 가게 이미지는 기기별 차이를 줄이기 위해 앱에 포함된 아이콘과 도형으로 표현했습니다.

## 후속 연동 범위

서버·다중 사용자 동기화·실제 인증/계정 보안·PG 결제/환불·카메라 QR 스캔·서버 서명 및 재사용 방지·은행 송금·푸시 알림·미디어 파일 첨부는 연결하지 않았습니다. QR 문자열은 `hantteok-demo:<요청ID>`이며 현재 기기의 데모 상태에서만 확인합니다. 고객지원 증빙은 링크 또는 참고 번호를 보관합니다. 운영자 처리와 정산 완료 버튼은 명시적인 모의 체험입니다. 취소·환불된 거래 목록 대신 완료 거래와 미사용 선결제 환불 신청을 구분하며, 사용 완료 거래의 취소·정산 조정은 후속 구현입니다.

16번 확장 기능(단체 직접 후원, 사용 보고, 감사 메시지, 후원 홍보, 공동 선결제, 공동체 피드·NFC)은 기획서의 후속 MVP 범위로 남겼습니다. 실제 서비스 적용 시 회원별 데이터 격리와 서버 트랜잭션으로 동시 사용·이중 차감을 방지해야 합니다.

## 코드와 검증

`lib/src/store.dart`: 상태·로컬 저장·거래 규칙, `models.dart`: 모델과 샘플 데이터, `pages/`: 기능별 화면, `ui.dart`: 공통 컴포넌트, `app.dart`: 테마·탭·반응형 앱 프레임입니다.

```powershell
flutter analyze
flutter test
flutter build web --release
flutter build apk --debug
```

`test/store_test.dart`는 차감 시점·초과액·중복 승인·인증·만료·메뉴 제한·환불·기기 저장 복원을 검증합니다. `test/app_test.dart`는 휴대폰 크기에서 로그인·탭 이동과 QR 사용 완료 흐름을 검증합니다.

`test/screens_test.dart`는 실제 한글 글꼴을 로드해 320px 화면의 주요 페이지와 결제 실패 후 재시도를 검증합니다. `flutter test --dart-define=CAPTURE_PREVIEWS=true`를 실행하면 `build/previews/`에 점검용 화면 이미지도 생성됩니다. 테스트 이미지는 위젯 렌더링 결과이며 실제 브라우저·휴대폰 실행 화면과는 차이가 있을 수 있습니다.
